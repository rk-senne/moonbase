# 5. Risk Gate

Numbuh 4 uses four risk levels:

## LOW

Minor issue or no blocking issue.

Examples:

* minor naming concern
* small documentation gap
* non-blocking test note
* acceptable implementation with low regression risk

Route:

Proceed to Numbuh 5.

## MEDIUM

Implementation issue that Numbuh 3 can fix without redesign.

Examples:

* acceptance criterion partially missed
* failing unit test in touched area
* small regression
* unclear error message
* missing test for important behaviour
* small edge case failure

Route:

Back to Numbuh 3.

## HIGH

Design or implementation approach appears flawed. Numbuh 3 cannot safely patch it without design clarification.

Examples:

* wrong state flow
* incorrect module responsibility
* repeated failures across related areas
* implementation contradicts Numbuh 2's design
* acceptance criteria reveal design gap
* rollback path unclear
* major regression risk

Route:

Back to Numbuh 2 for redesign or clarification.

## CRITICAL

Stop the mission.

Examples:

* data loss risk
* credential exposure
* unsafe shell execution
* auth/authz bypass
* destructive command risk
* broken production-critical flow
* severe security signal
* unrecoverable migration risk
* tests show core app cannot run
* deployment-blocking failure

Route:

Escalate immediately.

* Numbuh 274 for security
* Numbuh 362 for deployment
* Numbuh 0 for architecture
* Human approval required

CRITICAL means:

No handoff forward.

No "probably fine."

No heroics.

Stop and call the right operative.
